# 2.8 Summary (Chapter 2 Wrap-Up)

This section summarizes the essential CUDA C extensions established in Chapter 2. CUDA C integrates standard C/C++ with targeted language extensions (execution specifiers, launch configurations, built-in coordinate variables, and runtime APIs) for GPU orchestration.

---

## 2.8.1 Function Declarations

To instruct the compiler (`nvcc`) where a function executes and from where it can be invoked, CUDA provides three execution space specifiers:

> **Reference:** [2.5 Kernel Functions and Threading](./2.5_Kernel_Functions_and_threading.md) & [2.7 Compilation](./2.7_Compilation.md)

| Keyword | Executed On | Callable From | Description |
| :--- | :--- | :--- | :--- |
| `__global__` | **Device** (GPU) | **Host** (CPU) | Defines a **kernel function** (GPU entry point). Must return `void`. |
| `__device__` | **Device** (GPU) | **Device** (GPU) | Device helper function callable only from device code. |
| `__host__` | **Host** (CPU) | **Host** (CPU) | Standard host function (default if qualifier is omitted). |

**Multi-Target Compilation:** Combining `__host__ __device__` on a single function declaration instructs `nvcc` to generate **two distinct binary versions**: one for host CPU execution and one for device GPU execution. This pattern is standard for mathematical utility functions shared across host and device routines.

---

## 2.8.2 Kernel Call and Grid Launch

CUDA extends standard C function invocation syntax with chevron notation (`<<< ... >>>`) to configure execution grid hierarchy:

> **Reference:** [2.6 Calling Kernel Functions](./2.6_Calling_kernel_functions.md)

**Syntax:** `kernelName<<< gridDim, blockDim >>>(args...);`

- **`gridDim`**: Number of thread blocks in the grid.
- **`blockDim`**: Number of threads per block.
- **Combined:** Defines total grid concurrency (e.g., `(N + 255) / 256` blocks of `256` threads).

Chevron execution configuration applies exclusively to `__global__` kernel launches.

## 2.8.3 Built-in Coordinate Variables

When a kernel launches, all threads execute identical instruction sequences. To ensure each thread computes a distinct data element, hardware coordinate registers provide spatial identification:

> **Reference:** [2.5 Kernel Functions and Threading](./2.5_Kernel_Functions_and_threading.md)

- **`threadIdx`**: Local thread coordinate within its block.
- **`blockIdx`**: Block coordinate within the grid.
- **`blockDim`**: Block dimensions (thread count per dimension).

Combining these coordinates yields the global linear index:
`int i = blockIdx.x * blockDim.x + threadIdx.x;`

*(Note: Multidimensional grids (x, y, z) are covered in Chapter 3).*

## 2.8.4 Runtime Application Programming Interface (API)

The CUDA Runtime API provides standard C functions for device memory management and host-device data transfers:

> **Reference:** [2.4 Device Global Memory and Data Transfer](./2.4_Device_global_memory_and_data_transfer.md)

- **`cudaMalloc`**: Allocates linear memory on the GPU (VRAM).
- **`cudaFree`**: Releases allocated device memory back to the driver.
- **`cudaMemcpy`**: Performs synchronous memory transfers across the PCIe/NVLink bus (Host-to-Device, Device-to-Host, or Device-to-Device).

Runtime API calls return a `cudaError_t` status code, which must be evaluated to confirm operation success.

> **Official Reference:** Consult the official [CUDA C++ Programming Guide](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html) for complete API specifications.

## Pedagogical Philosophy of PMPP

The textbook outlines three foundational principles guiding its curriculum:

1. **Foundational Focus:** Chapter 2 introduces the minimal requisite concepts for functional CUDA C programming rather than exhaustive language mechanics.
2. **Concept Over Syntax:** Subsequent chapters emphasize parallel computing principles and architectural optimization, introducing CUDA syntax incrementally as algorithmic patterns demand.
3. **Official Documentation Alignment:** The text establishes architectural intuition to complement the official [CUDA C++ Programming Guide](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html) as the technical authority.
